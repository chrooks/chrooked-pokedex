# Playing the Ruleset on the Mac copy of Rejuvenation

Goal: run the same edited Rejuvenation on the Mac that runs on the Windows PC,
and keep the two in sync going forward.

## The model

Two different things, don't confuse them:

- **The Ruleset** (`ruleset/`) — the edits themselves. Source of truth, lives in git.
- **`patch/`** — build output the game reads. Generated by `apply`. Never hand-edited.

So sync = git syncs the Ruleset, and each machine builds its own `patch/`.
Hestia runs the edit UI and autocommits/pushes (see `docker-compose.yml` and
`deploy/ruleset-autocommit.service`); the PC and the Mac each pull and apply.

## One-time Mac setup

1. Python 3.11+ (repo requires >=3.11; macOS system Python is too old):

   ```bash
   brew install python@3.11
   ```

2. Clone and install:

   ```bash
   git clone git@github.com:chrooks/chrooked-pokedex.git
   cd chrooked-pokedex
   pip install -e .
   ```

3. Find the game folder. Mac Rejuvenation is mkxp-z, so the game files are
   usually inside the app bundle — right-click `Pokemon Rejuvenation.app` →
   Show Package Contents. You want the directory that contains `Data/`,
   `Graphics/`, and `Scripts/`, typically:

   ```
   /path/to/Pokemon Rejuvenation.app/Contents/Resources
   ```

   If macOS quarantined the bundle, the game can't write its compiled data on
   boot. Clear it once:

   ```bash
   xattr -dr com.apple.quarantine "/path/to/Pokemon Rejuvenation.app"
   ```

4. Register the target (`targets.json` is gitignored and per-machine, so this
   does not carry over from the PC):

   ```bash
   export REJUV_MAC="/path/to/Pokemon Rejuvenation.app/Contents/Resources"
   ```

## The sync loop

Every time you want the latest edits in the game:

```bash
cd ~/chrooked-pokedex
git pull && chrooked-pokedex apply --target "$REJUV_MAC" --engine rejuv
```

Worth aliasing to `rejuv-sync`.

Notes:

- `apply` wants a clean git tree in the target (`git_guard.py`). The game folder
  isn't a repo, so this is normally a no-op — add `--force` if it complains.
- The rejuv applier only **writes** into `<target>/patch/`. It never reads or
  modifies base game files, so this is safe to re-run and easy to undo (delete
  `patch/`).
- `patch/Init/chrooked_compile.rb` recompiles `patch/Data/*.dat` on next boot.
- Existing saves are fine — these are data-only changes.

## What about the behaviors (custom mechanics)?

Nothing extra to do — they ride along with the Ruleset.

The battle code lives in this repo at `references/rejuv-harness/`: one
`chrooked_<id>.rb` per mechanic plus `chrooked_00_core.rb`. All of it is
tracked in git, so `git pull` brings it, and `apply` copies it into
`patch/Mods/`. The game loads `patch/Mods/*.rb` after every base script, and
the core wraps base methods with Ruby `Module#prepend` — so **no base game
file is ever modified**.

```
references/rejuv-harness/*.rb  (git) --apply--> patch/Mods/*.rb
ruleset/*.yaml                 (git) --apply--> patch/Definitions/*.rb
```

Check the Apply Report afterwards. A behavior installs only if its `.rb` exists
and carries a `# chrooked:<id>` tag:

- implementation missing -> not installed, the ability keeps its honest
  `DATA ONLY` line in-game
- present but empty/untagged -> `blocked` in the report, nothing copied
- present and tagged -> `applied`, mechanic is live

## If the Mac should stay dev-tool-free

Not built, and probably not worth it. The alternative is having Hestia run
`apply` into a scratch dir (it needs no game install, since the applier only
writes), zip `patch/`, and serve it, so the Mac does one `curl | tar`. That's a
build pipeline standing in for a `git pull` — only build it if installing
Python on the Mac is genuinely off the table.
